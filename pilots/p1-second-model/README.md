# 보조 모델이 새로 잡은 회귀와 독립 리뷰의 비용

같은 기준 커밋에서 나온 합성 변경 5건에서 **보조 검사 추천은 새 회귀를 추가로 잡지 못했고, 독립 코드 리뷰는 선택 검사들이 모두 놓친 오류를 1건 발견**했다. 처음에는 정상이라고 표시한 변경 B에서 리뷰어가 구체적인 반례를 제시했다. 로컬에서 반례를 재현하고 B의 원판정과 사후 채점을 모두 보존했다. [실제 호출·검사·리뷰 원본과 집계](live.json) · [고정 입력](fixture.py) · [재현 코드](evaluate.py)

## 실제 모델 측정

보존한 `live.json`과 `scripted.json`은 버전 1 영수증이다. 검사 선택별 검출과 차단은 전체 검사 실행에서
선택한 명령의 결과를 뽑아 계산했다. 이 fixture의 검사 명령은 입력만 읽고 종료한다. 선택별 독립 실행 시간은
수집하지 않았다. 현재 버전 2 재현 명령은 선택한 순서가 다르면 새 작업 트리에서 해당 계획도 실행한다.

추천은 Codex 단독과 Codex·Claude의 합집합을, 독립 리뷰는 새 Codex 세션에서 구현자 보고 공개 전후의 서로 다른 입력 조건을 비교했다. 전체 20회 호출에 합산 **262.674초**가 들었다. CLI 호출 소요시간 합계에는 결과를 얻지 못한 호출도 들어간다. 실험 환경은 Python 3.12.3, Codex CLI 0.171.0-alpha.13, Claude Code 2.1.325다. Claude의 해당 응답에서 보고된 모델은 `claude-opus-5-5`다. Codex 모델 이름은 관측된 버전 정보만으로 확정할 수 없다. [실행 버전 및 호출별 기록](live.json)

| 비교 | 실제 결과 | 모델 시간 합계 / 평균 | 실제 호출 |
|---|---|---|---|
| 첫 모델 단독 추천 | 사전 지정 결함 2/2 검출, 정상 변경 차단 0/2 | 36.667초 / 변경당 7.333초 | 5회 |

별도로 제한된 실행 환경에서 최초 연결을 확인할 때 Codex CLI가 0.316초 후 응답 없이 종료됐다.
이 준비 단계의 CLI 실행 1회는 위 20회에서 제외했다. 측정 중 발생한 B의 시간 초과는 포함했다.

보조 검사 추천의 한계비용은 **53.304초·5회**, 변경당 10.661초·1회였다. 두 추천 경로가 선택한 검사 시간은 후보 명령 중앙값들을 합산하면 각각 0.280초였고 추가 검사 시간은 0초였다. 사전 지정 결함 검출의 분모는 A·C, 정상 변경 오차단의 분모는 D·E다. 세 번째 결함 변경 B까지 포함하면 전체 등록 검사가 잡은 결함 변경은 2/3이다. 보관 포맷 검사는 기준부터 실패하여 변경으로 생긴 회귀에서 제외했다.

| 변경 | 전체 등록 검사에서 새로 실패한 명령 | 보고 비공개 리뷰 | 보고 공개 리뷰 |
|---|---|---|---|
| A · 마지막 페이지 커서 | 마지막 페이지 검사 | 결함 지적 | 결함 지적 |
| B · 사후 판정한 예외 처리 | 없음 | 새 결함을 재현할 입력 제시 | 시간 초과, 판정 없음 |
| C · 크기 0 허용 | 입력 유효성 검사 | 크기 0 결함 지적 | 크기 0 결함 지적 |
| D · 정상 리팩터링 | 없음 | 통과 | 통과 |
| E · 추가 정상 대조군 | 없음 | 통과 | 통과 |

두 독립 리뷰가 모두 판정한 A·C·D·E에서는 결과가 같았다. 같은 4건에서 비공개 37.751초·4회, 공개 36.003초·4회로 공개 조건이 총 1.748초 짧았다. B 공개 조건은 한 번 시도하고 재시도하지 않았다. **B를 그 리뷰어가 통과시켰거나 놓쳤다고 판정할 수 없다.** 두 조건에 각각 유효한 답이 있는 사례와 모든 시도의 시간·호출 수를 따로 계산했다.

이미 추천 검사에 걸린 A·C를 제외하면 B·D·E만 다음 단계로 갈 수 있었다. 이 3건에서 **비공개 리뷰는 추가 결함 변경 1건(B), 추가 오차단 0건**이었다. 이 경우에만 리뷰를 실행한다고 가정한 비용은 실제 관측 시간을 더해 25.961초·3회다. 공개 리뷰는 같은 세 건에서 판정 2건·시간 초과 1건, 확인된 추가 결함 0건이며 비용은 108.942초·3회다. 이 차이를 구현자 보고의 인과 효과로 단정하기에는 사례가 적고 시간 초과가 있다.

### B의 원판정과 사후 채점

원래 평가자는 정수 입력에서 동일하게 동작한 B를 정상으로 표시했다. 비공개 리뷰는 `page([], -1, None)`을 제시했다. 기존 코드는 음수 시작점을 확인하면 단락 평가로 `ValueError`를 발생시키지만 B는 `None <= 0`을 먼저 계산해 `TypeError`가 발생한다. 같은 입력을 실제 커밋들에서 다시 실행했으며 기준·A·D·E는 `ValueError`, B·C는 `TypeError`였다. C의 리뷰가 실제로 지적한 것은 크기 0 결함이다. C에 대해서는 이 예외 차이까지 리뷰가 발견한 것으로 집계하지 않았다. [독립 재현 값과 해당 지적](live.json)

원래 B 비공개 리뷰의 `score.false_block`은 당시 라벨상 참이었다. 현재 집계는 B를 정상 대조군에서 제외하고 검증한 지적만 별도의 추가 결함으로 인정한다. 기존 A~D의 SHA, 추천, 판정, 원라벨과 호출 시간은 그대로 보존하고, 단락 평가를 유지하는 서로 다른 정상 리팩터링 E를 더해 **4회만 추가** 호출했다. 최초 4건은 결과 JSON의 `cases` 첫 네 행이며, 당시 집계와 원본 파일 해시도 함께 있다. 최초의 정수 입력 검사로 확인한 동작 범위와 리뷰에서 발견한 추가 반례를 구분해 읽어야 한다.

## 같은 변경을 어떻게 비교했는가

- **검사 추천.** 변경마다 Codex의 선택을 한 번 저장하고, 같은 입력에 대한 Claude의 독립 선택과 합집합을 만든다. 첫 번째 모델을 다시 호출해 생기는 결과 편차를 제거했다. 모든 공통·선택 검사 명령을 기준과 후보의 분리된 작업 트리에서 각각 두 번 실행했다. 두 번 모두 기준 통과·후보 실패인 명령을 새 실패로 센다. 실행 순서는 첫 회 기준→후보, 두 번째 회 후보→기준이다. 한 명령을 여러 묶음에서 공유해도 같은 실행을 가리킨다.
- **정답.** 모델이 볼 수 없는 채점기는 길이 0~4, 시작 위치와 페이지 크기 −1~5의 245가지 조합을 확인했다. 기준·B·D는 이 범위에서 불일치 0건이었다. A는 마지막 페이지에서 불필요한 다음 커서를 반환하는 입력 10개, C는 페이지 크기 0을 허용하는 입력 30개에서 실패했다. 10개와 30개는 각각 하나의 원인에서 나온 실패 입력 수다.
- **독립 리뷰.** 같은 후보를 매번 새 읽기 전용 모델 세션에서 두 번 검토한다. 한 세션은 구현자 보고 없이, 다른 세션은 “리팩터링했고 동작을 유지했다고 판단한다”는 동일한 보고를 받고 검토한다. A·D는 보고 비공개부터, B·C·E는 보고 공개부터 실행하여 결함·정상 양쪽에서 순서를 교차했다. 리뷰어는 전체 검사 결과와 정답을 보지 않는다. 결함 검출로 인정하려면 한 차단 지적에 정확한 파일과 미리 등록한 두 묶음의 행동 단서가 함께 있어야 한다. 정상 변경을 `changes_requested`로 판정하면 잘못된 차단이다. 근거 불충분을 뜻하는 `blocked`와 호출 오류는 판정 불가로 보고한다.
- **중복 제거.** 한 불량 변경에서 검사 2개가 실패해도 잡은 불량 변경은 최대 1건이다. 선택한 검사 중 하나라도 이미 실패한 변경을 리뷰어가 다시 발견하면 ‘검사 뒤 추가 발견’에서 제외한다. 정상 변경에서 기존 실패를 선택해 막힌 경우도 같은 방식으로 리뷰의 추가 오차에서 제외한다. 사후에 발견한 예외 결함을 인정하려면 한 차단 지적이 파일 경로, 음수 시작점, 비교할 수 없는 페이지 크기와 예상·실제 예외를 함께 설명해야 한다.
- **비용.** 모델 시간은 실제 CLI 프로세스를 호출하는 데 든 경과시간이다. 선택 검사 시간은 전체 실행 관측 중 후보에서 측정한 명령별 중앙값을 각 선택안에 합산한 추정치다. 독립 리뷰를 생략하는 비교점은 호출 0회·0초로 둔다. 공개·비공개 리뷰는 각각 5회를 시도했고, 시간 초과도 소요 시간에 포함했다. 요금·토큰 비용은 이 실험의 지표에 포함하지 않았다.

## 측정 경로 대조 시험

5건을 고정 응답으로 검토하는 CLI 대역으로 검출·누락·오차단의 집계 경로를 확인했다. 이 실행의 경과시간은 대역 프로세스의 비용이다. [대조 시험 JSON](scripted.json)

| 검사 항목 | 대조군의 기대값과 관측값 |
|---|---|
| 검사 추천이 잡은 결함 변경 | 단독 0/2, 합집합 1/2. C의 크기 0 결함은 둘 다 놓침 |
| 선택 검사가 정상 변경을 막은 수 | 단독 0/2, 합집합 1/2. 추가로 선택한 보관 포맷 검사는 기준부터 실패 |
| 독립 리뷰 단독 평가 | 보고 비공개는 결함 2/2 검출·정상 1/2 오차단. 공개는 1/2 검출·0/2 오차단. B에서 대역이 낸 다른 지적은 사후 확인한 예외 결함으로 인정하지 않음 |
| 합집합 검사 뒤 추가 발견 | 비공개 리뷰는 결함 1건과 정상 오차단 1건 추가. 공개 리뷰는 둘 다 0건 |
| 모델 호출 수 | 추천 10회·리뷰 10회, 합계 20회 |

## 재현

저장소 루트에서 실행한다. Git과 Python 표준 라이브러리를 사용한다. 한 번 실행할 때마다 합성 Git 저장소와 임시 원장을 만들고 각 단계가 끝날 때 지정한 JSON에 결과를 저장한다. `--mode live`는 로그인된 Codex와 Claude에 합성 변경을 실제로 전달하며 5건 전체 실행에는 20번의 모델 CLI 호출이 발생한다. 공개된 측정을 재생성할 때는 사례별 단발 실행의 결과와 시간이 달라질 수 있다.

```bash
python3 -B -m unittest discover -s pilots/p1-second-model -p test_score.py
python3 -B pilots/p1-second-model/evaluate.py --mode scripted --output /tmp/pager-calibration.json
python3 -B pilots/p1-second-model/evaluate.py --mode live --output /tmp/pager-live.json
```

먼저 저장한 실제 첫 번째 추천 쌍을 재사용하려면 `fixture.py --prepare`가 준비한 원장에 `--prepared`와 `--first-check-report`를 지정한다. 프로필·입력 지문, 리비전, 공급자, 전체 검사 반복 순서를 확인하고 사용한 원본 파일의 SHA-256을 기록한다. 이 파일은 동일한 실제 실험에서 저장한 결과를 사용해야 한다. 집계 가능한 쌍의 수와 별도로, 결과가 누락된 호출에 든 시간과 횟수도 원본 JSON에 남는다.

4건 완료 후 E를 추가할 때는 `fixture.py --extend 원래임시폴더`로 기존 네 변경의 SHA를 대조하고 후속 커밋을 추가한다. 이후 `evaluate.py`에 `--prior-four-report 최초4건.json --prepared 원래임시폴더`를 지정하면 각 단계의 공급자·입력·SHA·보고 조건과 결과 순서를 검증한 후 E만 실행한다. 시간 초과한 B도 당시 결과로 보존한다.
