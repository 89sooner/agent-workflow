# 중단 복구 재현 결과

구현 또는 검사 직후 제어기 프로세스를 종료하고 새 프로세스로 원장을 다시 열었다. PR과 배포는 대상에 변경을 적용한 다음 응답 또는 결과 저장을 끊었다. 각 시점의 진단 문구와 명령 횟수는 [실측 JSON](results.json)에 있다.

| 중단 사례 | 중단 직후 확인할 수 있는 효과 | 재개 결과 |
|---|---|---|
| 구현 직후 | 구현 호출 직전과 같은 HEAD에서 `app.py`가 달라졌다. 모델 응답과 검사 근거는 아직 없다. | 파일 쓰기 **총 1회**. 보존한 파일을 검사 1회·독립 리뷰 1회로 완료했다. 중단된 모델 호출과 예약 시간도 예산에 남았다. |
| 검사 통과 후 리뷰 전 | 통과한 검사 실행과 코드 지문이 원장에 남았다. | 처음부터 끝까지 구현 1회·검사 **1회**·리뷰 1회였다. 새 프로세스에서는 리뷰만 실행했다. |
| PR 생성·병합 응답 유실 | 생성 응답이 없을 때는 후보 커밋이 확인된 상태였다. 병합 응답을 잃었을 때는 원격 조회로 연결한 PR 번호까지 확인됐다. | 읽기 결과가 늦거나 모호한 경우에도 쓰기 요청은 **생성 1회·병합 1회**였다. 최종 병합 SHA는 bare Git 원격의 기준 브랜치와 일치했다. 이미 삭제된 작업 브랜치도 다시 만들지 않았다. |
| 배포 결과 불명 | 배포 시도와 병합 SHA가 기록됐다. 대상에서 읽은 버전이 다르면 대기했다. | 대상이 일치하는 버전을 보고한 뒤 상태 검사 1회로 완료했다. 불일치와 일치를 관측하느라 조회는 2회, 배포는 **총 1회**였다. 조회 명령이 없는 대조군은 두 번 재개해도 확인 대기였고 추가 배포·상태 검사는 0회였다. |

두 로컬 사례에서 같은 진단을 CLI로 두 번 조회하고 완료 후 다시 실행했을 때도 횟수는 같았다.
관제실에서는 실제 백엔드가 반환한 검사 영수증으로 리뷰 재개 안내를 확인했다.
같은 화면에 네 사례의 실측 진단 9개를 표시해 사유·효과·다음 행동이 JSON과 일치하는지도 검증했다.
화면 조회 중 POST와 신규 큐 작업은 각각 0건이었다. [브라우저 검증](../../tests/ui_scenarios.mjs)

## 재현

저장소 루트에서 아래 명령을 실행하면 임시 Git 저장소와 SQLite 원장을 만들어 다섯 시험을 수행한다. 모든 단언이 통과하면 JSON을 출력한다. 실행마다 Git SHA와 기록 시각은 달라질 수 있다.

```bash
python3 -B pilots/p1-recovery/replay.py --output /tmp/agent-workflow-recovery.json
```

로컬 사례는 파일을 쓰는 모델 대역과 실제 검사 프로세스를 사용한다. GitHub API 대역은 생성된 PR, 병합, 오래된 조회 응답을 보존하며, 병합 자체는 로컬 bare 원격에서 Git으로 수행한다. 배포 대상은 임시 파일에 적용된 SHA를 보관한다. 프로덕션 배포 서버나 실제 GitHub에 대한 요청은 이 재현에 필요하지 않다.
