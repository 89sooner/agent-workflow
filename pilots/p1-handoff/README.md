# 같은 중단 상태에서 기존 pickup과 새 인계 비교

목표는 모델이 돌아와 **처음으로 올바른 작업의 다음 동작을 시작하기까지** 걸리는 시간과 판단 오류를 측정하는 것이다. 이 파일럿은 사람이 아닌 독립된 모델 세션을 관측한다. 사용자 온보딩 시간이나 팀 생산성은 이 결과로 추정할 수 없다.

## 실제 모델 결과

작업을 고르기 전 모델이 받은 전체 `pickup` 입력 크기의 중앙값은 기존 3,593바이트, 새 형식 5,876바이트였다.
새 형식은 기존 조회 정보에 작업별 재개 정보를 추가한다. 작업을 고른 뒤에는 `resume-view ID`로 해당 작업 한 건만 읽을 수 있다.

두 방식 모두 6건에서 올바른 동작을 시작했다. 요청부터 첫 동작까지 중앙값은 기존 **7.178초**, 구조화 인계 **7.254초**였다. 사례마다 계산한 시간 차이의 중앙값은 **+0.097초**(구조화−기존)다. 구현 응답을 잃은 사례에서는 원본 조회 한 번을 줄였지만 여섯 사례 전체에 일관된 속도 개선은 나타나지 않았다. [실제 입력·선택·검사 영수증과 시간](live.json)

오래된 성공 근거가 실제로 남아 있던 사례는 방식당 한 건이며 두 모델 세션 모두 재검사를 골랐다. 기존 pickup에서 구현 중단 사례의 모델은 먼저 `show`에 해당하는 원본 기록을 확인한 후 검사 실행을 선택했다. 이 원본 조회는 요청 재설명으로 세지 않았다. 시간 초과와 미완료 시도는 없었다. 측정 환경은 Codex CLI 0.171.0-alpha.13, Python 3.12.3이며, CLI 응답에서 모델 세부 버전은 제공되지 않았다. 고정 응답으로 잘못된 작업·재설명·오래된 근거 사용을 일부러 발생시킨 계측 대조 시험에서도 각각의 오류가 기록되고 올바른 실제 검사가 한 번만 실행되는 것을 확인했다. ## 비교 설계

- 같은 Git 프로젝트의 요약 카드 작업과 별도의 서식 작업을 함께 등록한다. 두 방식 모두 “중단된 요약 카드 작업을 이어가라”는 같은 요청, 이전 세션의 작업 노트, 같은 선택 목록, 원장 원본 조회, 운영자에게 재설명을 요청할 기회를 받는다. 시험 대상 ID와 정답 행동은 모델에 보내지 않는다.
- 기존 P1 테스트로 구현 파일 쓰기 직후와 검사 결과 저장 직후에 제어기 프로세스를 실제로 종료한다. 별도 사례에서는 검사 통과 뒤 주석을 바꿔 오래된 성공 기록을 남긴다. PR 생성·병합 응답 유실은 상태를 가진 로컬 호스트 대역과 bare Git 원격, 배포 응답 유실은 실제 SHA를 기록·조회하는 로컬 명령으로 재현한다. [중단 상태 준비와 행동 실행](scenarios.py) · [기존 P1 복구 재현](../p1-recovery/README.md)
- 사례마다 Git 작업 트리, 닫은 SQLite 원장, 로컬 대상 상태를 저장하고 각 방식 전에 같은 절대 경로에 별도 복사본을 복원한다. 레코드와 Git·호스트 상태의 해시가 같아야 진행한다. 여섯 사례에서 선행 방식을 교대로 바꾼다. 실제 기록에서는 수정 전 Python 패키지로 실행한 `pickup`과 현재의 `pickup --classic`이 같은 상태에서 동일한 JSON을 반환하는지 먼저 대조한다.
- 측정은 `pickup` 프로세스를 시작하기 직전에 단조 시계로 시작한다. 조회 시간, 모델 응답 대기, 잘못된 선택 이후의 재시도, 필요했던 원본 조회·재설명을 모두 포함한다. 로컬 시험은 등록된 검사 또는 별도 리뷰 프로세스에 진입할 때 시간을 기록한다. PR 시험은 모의 호스트의 실제로 저장된 응답을 읽을 때, 배포 시험은 버전 명령을 실행할 때 기록한다. 동작을 수행한 뒤 결과 지문, 원격 PR·SHA, 또는 대상 조회 횟수까지 확인해야 성공으로 채점한다.
- 모델은 새 도구 없는 세션에서 한 번에 동작 하나를 제안한다. 원본 조회·재설명·잘못된 선택 이후에는 이전 대화와 관측을 같은 형식으로 다시 제공한다. 한 시험당 최대 3회 선택하며, 올바른 첫 동작까지의 시간은 시작이 확인된 경우에만 계산한다. 부적절한 쓰기 제안은 기록하고 차단한다. 조회만으로 원격 쓰기나 운영 배포가 발생하지 않는다.
- **잘못 고른 작업**은 다른 작업에 실제 작업 동작을 제안한 횟수다. 작업 확인을 위한 원본 열람은 별도로 센다. **재설명**은 모델의 요청에 따라 운영자 대역이 정해 둔 목표·범위를 다시 설명한 횟수다. **오래된 근거 사용**은 독립적으로 현재성을 잃었다고 확인한 검사 결과를 현재 통과 증거로 사용한다고 명시하거나, 그 검사에 기대어 독립 리뷰를 시작하려 한 횟수다. 이력 조회와 재검사는 오래된 근거 사용으로 세지 않는다.
- 각 사례를 방식마다 한 번씩 실행하므로 모델 시간 변동과 사례별 난이도에 민감하다. 측정 시간에는 사업자가 응답하는 지연이 포함된다. 모델이 고른 행동을 안전하게 수행하는 계약 시험이며, 운영자가 자유롭게 작업하는 시간을 측정한 결과와는 구별한다. 이전 노트는 양쪽에서 같고 사람의 인계 작성 시간은 수집하지 않았다. 각 요청의 실제 pickup 지연과 입력 바이트는 JSON에서 확인할 수 있다.

## 재현

저장소 루트에서 실행한다. 스크립트 모드는 두 형식 모두에서 읽을 수 있는 기존 검사·릴리스 상태로 행동을 선택해 측정 경로를 확인한다. 고정된 선택기의 소요 시간은 실제 모델의 성능 비교에 사용하지 않는다.

```bash
python3 -B -m unittest discover -s pilots/p1-handoff -p test_score.py
python3 -B pilots/p1-handoff/evaluate.py --mode scripted --output /tmp/p1-handoff-calibration.json
python3 -B pilots/p1-handoff/evaluate.py --mode live --timeout 75 --output /tmp/p1-handoff-live.json
```

실제 모델 실험은 로그인된 Codex에 합성 인계 자료만 전송한다. 처음 12회 선택하고 추가 조회·조정이 필요한 경우 최대 36회 호출한다. 이전 버전의 Python 패키지가 있으면 `--legacy-engine /path/to/before`를 지정한다. 이 경로는 `agent_workflow/` 디렉터리의 부모다. 생략하면 공개 CLI의 `pickup --classic`이 기준선이다. 실행마다 시간, Git SHA, 영수증 지문은 달라질 수 있다.
