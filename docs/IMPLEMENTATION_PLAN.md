## 검증 원칙

- 실제 임시 Git 저장소·자식 프로세스로 변경과 실패를 관찰한다.
- UI는 격리 상태와 가짜 외부 응답으로 확인하며 실제 작업 큐를 변경하지 않는다.
- 자동 복구가 새 목표·권한·배포 대상을 만들거나 실패를 통과로 바꾸지 못한다.
- 완료 기록은 검사·리뷰한 코드와 연결하고, 이후 소스 변경은 다시 검증한다.
- 회사 서버·운영 배포·외부 알림의 실제 연결은 구체적인 대상과 자격 증명이 있을 때 검증한다.
- 공동 서버용 다중 사용자 인증·조직 운영은 개인 WSL 실행기의 무인 운영과 별도 배포 범위다.

## 실제 검증에서 반영한 수정

- 중단된 구현을 검사한 뒤 독립 리뷰로 이어가는 실제 자식 프로세스 시험을 추가했다.
- staged 내용이 작업 파일에서 가려진 경우도 범위 검사에 포함했다.
- 문서 경로의 심볼릭 링크가 금지된 파일을 가리키면 쓰기 전에 거부한다.
- 실제 브라우저 연속 검사에서 종료된 서버의 TIME_WAIT를 확인했다. 포트 점검에서 종료 연결과 살아 있는 listener를 구분하도록 수정했다.
- 사용자 systemd가 offline이므로 Bash 로그인 시 시작하는 방식도 추가했다. 기존 프로필 내용·심볼릭 링크를 보존한다.
- `out of credits`는 재호출하지 않는 사용량 오류로 분류한다. 이 개발 세션의 승인 검토 크레딧 오류로 실행되지 못했던 검사는 사용자의 재개 요청 후 정상 승인 경로로 실행했다.
- 최초 Claude 독립 리뷰에서 요구 사항 충족을 확인했다. 함께 나온 제어 경쟁 조건·오류 분류·DB 잠금·경로 안내·기존 변경 보존 항목을 보완했다.
- Claude의 별도 세션 한도로 후속 검토가 불가능해 검토자를 새 Codex 읽기 전용 세션으로 명시적으로 전환했다. 실제 검토 실행 기록을 요구하며 기존 Claude 검토를 최신 코드의 결과로 복사하지 않는다.
