# 화면에서 프로젝트 연결하기

2026-11-04 · 사용성 계획 UX-01~03의 첫 사용 개선. 이 기능을 포함한 소스로 실행한 관제실에 적용된다. 기존 운영 서버의 반영 여부는 별도로 확인한다.

## 연결 버튼이 보이지 않으면

이 기능이 포함된 소스로 실행 중인지 먼저 확인한다. 오래된 서버는 새 UI나 capability API가 없을 수 있다.
기존 운영 서버를 임의로 갱신하지 말고, 최신 소스의 별도 checkout에서 아래 `watch` 예시처럼
별도 observer home과 빈 포트로 시작할 수 있다. 새 화면이 보여도 서버가 기존 버전이면 설정 API가 동작하지 않는다.
화면에서 권한 조회 오류가 나면 [운영 절차](OPERATIONS.ko.md)의 소스·HTTP 자산·서버 모드 확인을 따른다.

## 처음 연결할 때

1. 실행 중인 관측 전용 관제실의 `/mission`을 연다. 왼쪽 **프로젝트 연결**을 누른다. 기록이 하나도 없으면 **첫 프로젝트 연결**도 표시된다.
2. **프로젝트 폴더 경로**에 관제실 서버에서 접근할 수 있는 실제 절대 경로를 입력한다. WSL 서버에는 WSL 경로를 사용한다. 브라우저가 컴퓨터 전체를 검색하거나 폴더를 자동으로 읽는 기능은 아니다.
3. **사용 도구**를 선택하고 화면에 표시되는 지원 범위를 확인한다.
4. OpenCode라면 **연결하고 관측하기**를 누른다. 기본 주소는 `http://127.0.0.1:4096`이다. 다른 주소나 인증을 사용하면 **서버 주소·인증 설정**을 펼쳐 수정한다. 연결 이름은 선택 사항이다.
5. Codex·Claude라면 **프로젝트 기록 찾기**를 누른 뒤 발견된 작업 기록을 선택하고 **연결하고 관측하기**를 누른다. 후보를 찾았다는 것만으로 설정을 저장하지 않는다.
6. 연결이 저장되면 해당 출처로 이동한다. 왼쪽 세션/작업을 선택해 담당자·그래프·실행 기록을 확인한다. 이후 지원되는 새 기록은 자동으로 표시된다.

OpenCode 서버와 해당 프로젝트는 이미 사용 중이어야 한다. 관제실이 서버나 모델을 자동 시작하지 않는다. 기본 주소 외 서버는 실제 주소를 입력해야 한다. 인증이 있는 서버는 비밀번호 자체 대신 **관제실 서버에 전달된 환경변수 이름**을 입력한다. 환경변수 준비는 최초 서버 설정의 일부이며 UI가 운영 프로세스의 환경을 바꾸지 않는다.

| 사용 도구 | 자동으로 보이는 범위 |
|---|---|
| OpenCode | 한 번 연결한 서버·프로젝트의 네이티브 세션과 응답·도구 상태. 세션마다 workflow 작업 등록 불필요 |
| Codex·Claude | `/mission`은 workflow 작업·실행, `/sessions`는 등록한 프로젝트의 훅/플러그인 이벤트. 일상 세션에는 WP 불필요 |

workflow 후보는 기존의 제한된 알려진 위치·프로세스·저장된 연결에서 찾는다. 임의 위치의 기록이 후보에 없으면 기존 `connect PROJECT --ledger STATE_HOME` 명령으로 명시적으로 연결할 수 있다. 디스크 전체 검색은 하지 않는다.

## 빈 화면이나 오류가 보일 때

| 표시 | 다음 행동 |
|---|---|
| 연결된 기록 없음 | 프로젝트 연결에서 도구와 프로젝트를 지정 |
| 연결됐지만 세션/작업 없음 | 같은 프로젝트에서 새 세션을 시작하거나 실제 서버·폴더와 선택한 연결이 일치하는지 확인 |
| 검색 조건에 맞는 작업 없음 | **검색 조건 초기화**로 검색어와 상태 필터를 함께 해제 |
| 인증 확인 필요 | 인증 환경변수 이름과 서버 프로세스에 전달된 값 확인 |
| 서버 연결 확인 필요 | 기존 서버의 상태와 주소를 확인하고 **다시 연결** 또는 **기록 새로고침** |
| 프로젝트 경로 확인 필요 | 서버가 접근할 수 있는 실제 절대 경로로 수정 |
| 지원 범위 확인 필요 | OpenCode 버전/API 또는 도구별 지원 설명 확인 |

오류 화면에는 실제 오류와 마지막 성공한 조회 시각을 표시한다. 과거 조회 성공 기록이 없으면 미기록으로 표시한다. 재조회는 작업을 재실행하지 않는다. 빈 세션 목록만으로 프로젝트를 잘못 지정했다고 단정하지 않는다.

## 관측 설정과 작업 실행 권한

| 서버 방식 | 연결 설정 UI | 작업 등록·실행 |
|---|---|---|
| `watch` | 허용. observer home의 연결 파일만 저장 | 차단, worker 없음 |
| `serve --read-only` | 변경 차단. 지원 범위와 제한 안내 | 차단, worker 없음 |
| 일반 `serve` | 허용 | 서버 자신의 기본 원장에만 관리 링크 표시. 외부 연결은 관측 전용 |

새 관측 서버가 필요할 때만 별도 home과 빈 포트로 시작한다.

```bash
python3 -m agent_workflow --home /path/to/observer watch --port 8878
```

연결 설정과 관제실이 같은 observer home을 사용해야 한다. 일반 `serve`는 worker도 시작하므로 관측 전용 서버를 대신하는 명령이 아니다. 운영 8765·8776·8777을 종료해 포트를 확보하지 않는다.

기존 읽기 전용 서버의 모든 POST 차단은 유지한다. `watch`에서는 동일 출처·요청 토큰으로 검증한 연결 설정 POST만 허용한다. 관측 조회는 GET이며 작업·큐·원격 OpenCode 실행을 생성하거나 변경하지 않는다.

## 구현 범위와 후속 단계

이번 범위는 연결 UI, 빈 상태·실패 진단, 관측/관리 동선 분리다. 프로젝트 통합 보기(UX-04), 확인 요청함(UX-05), 추가 3D 가독성(UX-06), URL/재방문 개선(UX-07), SSE·영구 이력·팀 서비스는 후속이다.

브라우저 자동 검사로 동작을 검증한다. 계획의 ‘처음 사용하는 사람의 80%가 5분 이내 성공’ 목표는 실제 신규 사용자 조사가 필요하며 자동 검사 통과로 달성했다고 보지 않는다.
