## 지금 바로 쓸 수 있는 범위

목표와 완료 조건을 정한 뒤 등록한 프로필을 선택한다. 도구가 별도 폴더에서 구현과 검사,
독립 리뷰, 인계를 연결한다. 설정한 횟수와 시간의 범위를 넘으면 중단 이유를 남긴다.
프로젝트와 작업의 적절성은 사용자 또는 대화 중인 에이전트가 판단한다.

## 외부 대상이 정해졌을 때 연결할 범위

1. 실제 Git 호스트와 저장소, 기준 브랜치를 확인한다.
2. 배포할 프로그램과 적용 버전을 확인할 명령을 정한다.
3. 대상 프로젝트의 배포 실패 복구 절차를 정한다.
4. 알림이 필요하면 실제 수신 채널과 사용할 명령을 정한다.
5. 지정한 대상으로 릴리스와 상태 확인을 한 번 검증한다.

사용자는 현재 외부 대상을 정하지 않았다고 답했다. 임의의 클라우드 자원이나 계정을
만들지 않았다. 현재 WSL에서의 로컬 실행은 이 결정을 기다리지 않고 사용할 수 있다.
공용 서버의 인증·조직 권한·SSO와 GitLab·Bitbucket 전용 릴리스는 별도 확장이다.

## 완료 표시를 읽는 법

`completed`는 기록 당시의 완료이고 `completion_is_current`는 현재 코드와의 일치다.
지난 `AW-AUTOMATION-001`은 검사 후 직접 커밋하면서 HEAD와 index가 바뀌었다.
따라서 과거 검사 상태를 현재 검사로 표시하지 않는다. 당시 게시 기록은 소스 내용이
같았음을 별도로 확인했다. 이 기록을 무조건 현재로 바꾸거나 완료된 작업을 덮어쓰지 않는다.
이번 `KB-WEB-FIXTURE-R29`는 검증된 worktree를 유지하므로 현재 근거 세 값이 모두 `true`다.
