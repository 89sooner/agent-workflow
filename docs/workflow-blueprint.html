작업현재 구현완성형 목표
작업 고르기사용자·대화 중인 AI가 문서를 읽고 등록정해 둔 프로젝트·우선순위·선행 조건으로 후보와 실행 계획 생성
환경·규칙 준비작업 폴더·검사·포트·범위 검사를 따로 준비프로젝트 설정에서 worktree·환경·파일 소유권·실행 시간대를 준비
구현·독립 리뷰Codex·Claude 연결과 제한된 수정 반복 지원기존 실행기에 모델 설정·사용량 관찰·허용된 전환 정책 추가

04 / RESULT

사용자가 받게 될 것

“완료”라는 한 줄에 더해, 무엇을 바꿨고 무엇을 확인했는지 같은 화면에서 확인하게 됩니다.

  • 작업 결과 — 변경 파일·검토용 차이·기능 설명
  • 확인 근거 — 실제 검사 결과·독립 리뷰·해당하는 브라우저 증거
  • 적용 위치 — 로컬 브랜치 또는 PR·병합 커밋·배포 버전
  • 다음 세션 인계 — 마지막 상태·남은 일·다음 행동
  • 개입이 필요할 때 — 중단 이유·이미 시도한 일·결정할 선택지

자동으로 이어갈 범위도 정합니다.

미리 정한 범위 안의 작업과 복구는 계속 진행합니다. 새 권한, 예산 확대, 다른 트랙의 파일 변경처럼 기존 조건으로 결정할 수 없는 일은 상태를 보존하고 판단을 요청합니다.

다음 WP 자동 실행도 프로젝트·작업 수·시간·예산과 선행 조건을 설정한 경우에만 이어가도록 설계합니다.

FIRST작업 하나를 안정적으로 끝내기

프로젝트 설정 + 작업 환경 준비 + 중단 복구

NEXT마감과 반복 운영 연결하기

브라우저 검사 + 문서·인계 + 실행 제어·알림

THEN연속 작업과 팀 환경 확장

WP 의존 관계 + 병렬 작업 + 사내 연결·공동 사용

현재 구현의 근거와 설계 가정 보기
  • 사용 안내서 — 2026-10-08 현재 기능·명령·제약. 이 페이지의 “추가 예정”은 구현 사실이 아닌 제안입니다.
  • runner.py — 에이전트 호출, 실제 검사, 제한된 수정, 유효한 검사·리뷰 재사용.
  • daemon.py / server.py — 단일 worker·대기 취소·loopback 대시보드. 현재 데몬은 이전 실행을 interrupted로 기록하고 자동 재시도하지 않습니다.
  • cli.py / release.py — 작업 등록, 인계 생성, 설정된 릴리스. 현재 run과 pipeline 모두 릴리스 설정이 있으면 실행합니다.
  • Katakuri 실제 실행 결과 — Claude 시간 초과 뒤 부모 에이전트가 검사·기록 정정·재개를 수행했습니다. 복구 개입 1회, 무감독 성공 아님, 병합·운영 배포 없음.
  • 설계 가정 — 모델 비용·잔여량은 CLI가 제공하는 범위에서 관찰합니다. 정확한 사용량을 제공하지 않는 연결에는 호출·시간 한도와 알 수 없음 상태를 사용해야 합니다. 영구적인 오류는 성공을 보장할 수 없습니다.
