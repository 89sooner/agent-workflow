# 유사 앱 조사와 agent-workflow 개선 후보

조사일: 2026-11-05 (Asia/Seoul). 비교 소스: agent-workflow `388752203b3bc98eda45b4c4dd60f9ea68ef74bc`.

이 문서는 웹 조사 결과와 개선 제안이다. 기능 구현·배포 계획의 승인을 의미하지 않는다. 현재 사용법은 [문서 목록](README.md), [세 도구 플러그인 안내](NATIVE_PLUGINS.ko.md)를 따른다. 기존 [2026-10-30 조사](OBSERVABILITY_RESEARCH.ko.md)는 당시 기록으로 보존한다.

## 결론

유사 앱은 세션 관측, 병렬 작업·리뷰 관리, 사무실 시각화, 실행 분석으로 나뉜다. 우리 프로젝트에는 이미 다중 원장 연결, 상태별 3D 공간, 확인 요청 필터, 실행 기록 재생이 있다. 사내 OpenCode·Claude Code·Codex 일상 작업 관측의 다음 개선은 최초 연결 진단, 통합 진입점, 사람을 기다리는 세션 안내, 결과 확인에 우선순위를 두는 것이 적합하다.

추천 조합은 ccdeck의 대기 중심 화면, Agent of Empires의 세션 탐색, Pixel Agents의 실제 활동 표현, Paradev의 변경 결과 연결이다. 이는 조사 자료를 바탕으로 한 프로젝트 적용 판단이다.

## 조사 범위와 방법

- 질문: 유사 앱은 무엇이며, 어떤 기능을 현재 agent-workflow에 차용하면 사내 일상 작업 관측이 편해지는가?
- 웹 검색 각도: `AI coding agent monitoring dashboard Claude Codex OpenCode`, `Vibe Kanban features review coding agents worktree`, `Superset terminal coding agents workspace notifications`.
- 검색 결과에서 공식 사이트·공식 저장소·공식 문서를 선택해 본문을 확인했다. 제품명 변경과 서비스 종료 여부도 공식 출처로 확인했다.
- 로컬 README, 기존 조사, `agent_workflow/native.py`, `connections.py`, `onboarding.py`와 비교해 기존 기능과 추가 제안을 구분했다.
- 외부 앱은 직접 설치·실행하지 않았다. 아래 기능은 공식 자료의 설명이며 성능·안정성·설치 성공을 검증한 결과가 아니다. 가격·도입률 순위는 조사하지 않았다.

### 지원 범위·서비스 상태의 주의점

- Vibe Kanban은 운영 회사 bloop 종료와 커뮤니티 중심 전환을 공식 발표했다. 공지는 2026-04-10자로, 로컬 작업 공간 지속 및 원격 서비스 제거를 설명한다. 현재 원격 서비스 가용성은 직접 검증하지 않았다. [공식 공지](https://www.vibekanban.com/blog/shutdown)
- Superset의 공식 저장소는 Paradev로 연결되며 README가 이전 이름을 명시한다. Apache Superset과는 별개다. [공식 README](https://github.com/ParadevAI/Paradev)
- Pixel Agents는 Claude Code를 현재 기준 구현으로, Codex 등은 로드맵으로 설명한다. 다중 도구 지원 완료 사례로 취급하지 않는다. [공식 README](https://github.com/pixel-agents-hq/pixel-agents)
- ccdeck은 Claude의 현재 입력 대기와 Codex rollout 로그 기반 기록의 차이를 명시한다. 모든 공급자에서 동일한 실시간 상태를 얻는다고 해석하지 않는다. [공식 사이트](https://ccdeck.dev/)

## 권장 진행 순서와 수용 기준

먼저 P0 다섯 항목을 하나의 사용자 흐름으로 설계한다.

관제실 접속 → 발견된 프로젝트 선택 → 연결 진단 → 평소 도구 사용 → 사람 개입 알림 → 해당 세션 복귀.

1. 사용자가 포트나 state home을 몰라도 연결된 프로젝트에 접근한다.
2. 최초 프로젝트 연결 후 새 세션마다 에이전트를 등록하지 않는다.
3. 관측 실패 시 실패 단계·마지막 수신 시각·다음 행동을 확인한다.
4. 입력 대기를 일반 idle과 구분하고 대기 시간을 보여 준다.
5. 동일 요청에 대한 반복 알림을 억제하고 사용자가 알림을 끌 수 있다.
6. 오래된 관측값을 현재 실행 중으로 표시하지 않는다.
7. 관측 연결만으로 작업이나 큐 worker를 실행하지 않는다.

현재 8776/8777은 원장과 실행 모드가 다르다. 단일 진입점은 화면과 연결 구성을 통합하는 제안이며 DB를 합치거나 실행 모드를 변경한다는 뜻이 아니다. 구체적인 운영 통합은 별도 검증이 필요하다.

## 적용 원칙과 미확인 사항

- 자동 발견은 도구·프로젝트 후보 발견과 사용자가 연결한 범위의 세션 자동 관측으로 구분한다. 로컬 대화 전체를 읽는 방식은 현재 메타데이터 중심 수집 정책과 다르므로 별도 선택 옵션으로 검토한다.
- 실제 도구 이벤트가 있을 때만 읽기·수정 동작을 사용한다. `running`만 확인되면 일반 작업 동작을 사용하며, 역할·이름·내부 대화를 추정하지 않는다.
- 세션 응답 종료와 작업 검증 완료를 구분한다. 공급자별 수집 범위도 표시한다.
- 토큰·비용·오류 지표는 누락을 0으로 바꾸지 않는다. 추정 비용은 가격 기준과 추정 여부를 표시하며 구독 청구액과 동일시하지 않는다.
- 외부 앱의 코드를 복사하거나 라이브러리를 도입하는 제안은 아니다. 실제 재사용 시 해당 코드·자산의 라이선스를 별도 확인한다.
- 기업 SSO·팀 권한 등 사용자가 이전에 제외한 범위는 이번 우선순위에 넣지 않았다.
- 외부 앱의 실제 설치 품질, 대규모 세션 성능, 각 호스트 버전 호환성은 미검증이다. 개선 효과와 개발 비용 역시 사용자 테스트·설계로 확인해야 한다.
