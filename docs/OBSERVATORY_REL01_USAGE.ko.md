# 통합 관제실·연결 진단·알림 사용 안내

> 상태: 로컬 구현·검증, 출시 게이트 미완료. 2026-11-05. 사용자 파일럿·전체 출시 판정은 운영 반영과 구분한다.

이 문서는 `codex/observatory-usability-20261105`에서 구현한 기능을 설명한다. 운영 반영은 [운영 절차](OPERATIONS.ko.md)의 실제 배포 SHA·health 증거로 확인한다. 전체 구현 범위는 [구현 계획](OBSERVATORY_IMPLEMENTATION_PLAN.ko.md)에서 확인한다.

## 시작과 화면 이동

검증된 개발 checkout 또는 해당 소스로 만든 패키지에서 Python 3.11 이상을 사용한다. 개발 예시:

```bash
cd /tmp/agent-workflow-observatory-20261105
/home/roqkf/.pyenv/versions/3.12.3/bin/python3 -m agent_workflow \
  --home /tmp/my-agent-observer watch --port 8892
```

`http://127.0.0.1:8892/overview`가 통합 진입점이다. 이 예시는 실제로 실행해 둔 서버 주소가 아니다. `watch`는 큐 worker를 시작하지 않는다. `serve`는 실행 모드에 따라 worker가 시작되므로 관측용 명령과 혼동하지 않는다.

- **통합 관제실:** 프로젝트별 관리형 작업·일상 세션을 함께 표시한다. 항목을 선택하면 기존 상세 화면으로 이동한다. 일부 연결 실패는 해당 오류와 나머지 결과를 함께 보여 준다.
- **관리형 작업:** `/mission`에서 작업·실행 이력·검사 근거를 확인한다. 동일 task ID라도 원장이 다르면 별도 항목이다.
- **일상 세션:** `/sessions`에서 도구 필터, 확인 요청함, 상태별 3D 공간·이력을 사용한다. WP 등록은 필요 없지만 프로젝트 연결·훅/플러그인 설정은 필요하다.

## 프로젝트 연결과 진단

프로젝트 연결 절차는 [첫 연결 안내](CONNECTION_SETUP.ko.md)와 [세 도구 플러그인 안내](NATIVE_PLUGINS.ko.md)를 따른다. 정확한 대기 시작 시각은 새 코어가 기록한 상태 전이가 필요하다. 구버전 기록의 시작 시각은 추정하지 않고 미기록으로 표시한다.

통합 화면 또는 일상 세션의 **프로젝트 관측 연결 진단**을 펼친 뒤 도구와 서버 컴퓨터의 프로젝트 절대 경로를 입력한다. **연결 진단 실행**은 조회만 수행하며 설치·등록·작업·worker를 실행하지 않는다.

| 단계 | 확인하는 근거 |
|---|---|
| 프로젝트 경로 | 관제실 서버에서 폴더가 보이는지 |
| 프로젝트 등록 | 관측 home에 해당 프로젝트·도구가 등록됐는지 |
| 관측 설치 | 직접 훅은 등록 명령과 설정 파일의 일치 여부. 플러그인 로딩은 자동 보증하지 않음 |
| 호스트 활성화 | 호스트의 신뢰·재로딩 여부는 미확인. API 연결은 해당 없음 |
| 첫 이벤트 수신 | 해당 도구·프로젝트의 과거 수신 이력. 현재 실행 중임을 뜻하지 않음 |

도구·경로를 바꾸면 이전 결과를 지운다. `미확인`은 실패나 성공을 단정할 수 없다는 뜻이다. Codex는 프로젝트 신뢰와 `/hooks` 검토가 필요하다. 진단 화면이 대신 승인하지 않는다.

## 확인 요청과 대기 시각

질문·승인·오류 확인 요청이 일반 유휴보다 먼저 표시된다. 시작 시각이 확인된 요청은 오래된 것부터, 동률이면 ID 순으로 표시한다. 시각이 없으면 확인된 요청 뒤에 미기록으로 표시한다.

같은 상태를 반복 조회하거나 도구 정보가 바뀌어도 시작 시각을 초기화하지 않는다. OpenCode 질문·승인 API 일부가 실패하면 이전 기록을 덮어쓰지 않고 현재 상태를 미확인으로 표시한다. 오래된 관측을 현재 대기로 집계하지 않는다.

## 알림 켜기·끄기

일상 세션 화면의 **알림 켜기**를 누르면 브라우저 권한을 요청한다. 허용한 경우 입력·승인·오류·세션 종료의 새 전이를 알린다. 권한이 거절되면 화면에 다음 행동을 안내한다.

- 첫 화면에 이미 있던 기록은 알리지 않는다. 처음 조회 이전의 오래된 상태는 복구돼도 재생하지 않는다. 서버의 첫 관측 시각 이후 생긴 새 세션 요청은 첫 발견이어도 알림 대상이다.
- 알림을 켠 동안 숨겨진 탭에서도 관측 조회를 계속한다. 3D 움직임의 숨김·reduced-motion 정책은 유지한다. 브라우저 종료 후 알림은 제공하지 않는다.
- 같은 origin의 여러 탭은 Web Locks와 로컬 저장소로 동일 전이 알림을 한 번만 표시한다. Web Locks 미지원 시 화면 안 안내만 제공한다. 다른 포트·origin 간 중복 억제는 지원하지 않는다.
- 한 탭에서 **알림 끄기**를 누르면 같은 origin의 다른 탭도 꺼진다.
- 알림을 선택하면 해당 세션으로 이동한다. 실제 승인·입력은 원래 도구에서 수행한다.
- 알림 수신 이력은 로컬 저장소에 최대 1000개까지 유지한다. 전체 대화·도구 입력은 저장하지 않는다.

## 세션 계층과 원래 도구로 복귀

일상 세션 화면의 **부모·하위 에이전트 탐색**을 펼치면 현재 필터의 부모·자식 관계를 볼 수 있다. 항목을 누르면 같은 세션 상세와 3D 선택으로 연결된다. 공급자·소스·원래 세션 ID가 같은 범위에서만 부모를 연결한다. 부모가 삭제되거나 필터 밖이면 안내를 표시하고, 순환 관계는 한 연결을 분리해 모든 세션을 보존한다.

상세의 **원래 도구로 복귀**에서 프로젝트 경로 또는 세션 ID를 복사해 해당 도구로 돌아간다. 클립보드가 막히면 표시된 값을 직접 선택해 복사한다. 검증되지 않은 URI·shell 명령으로 세션을 실행하지 않는다. 현재 세 도구 모두 이 복사·안내 경로를 제공하며 호스트별 직접 복귀 링크는 미지원이다.

하위 에이전트 이벤트에 이름이 없는 경우 이전에 받은 이름을 유지한다. 화면 이름은 관측 저장 이름이며 실제 배정 역할을 추정한 결과가 아니다.

이 범위의 구현·타입·단위·Chromium 검증 증거는 작업 원장에 기록한다. 독립 검토의 최종 판정은 해당 패키지와 통합 감사 기록을 따른다. 운영 반영 여부와 구분한다.

## 프로젝트 공간과 실제 활동

**프로젝트 공간**에서 프로젝트를 선택하면 목록·요약·3D 입력이 같은 조건으로 바뀐다. Git worktree는 공통 프로젝트로 묶고 각 세션 상세에는 실제 경로를 유지한다. 선택한 프로젝트는 주소에 보존된다. 확인 요청함의 건수도 현재 프로젝트·도구·검색 조건을 따른다. **종료 이력 포함**을 켜면 종료 세션이 목록·요약·공간 목록에 함께 포함된다.

신선한 도구 시작 이벤트가 있을 때 읽기·수정·명령 실행을 표시한다. 읽기는 머리·손 자세로, 수정은 머리 위 초록 상자, 명령은 금색 팔면체, 일반 작업은 회색 구체와 활동명으로 구분하며 도구 종료 후 일반 작업으로 돌아간다. 오래된 상태와 reduced-motion에서는 지속적인 활동을 과장하지 않는다.

3D는 최대 12명을 표시한다. **목록 보기**는 WebGL을 중지하고 전체 작업자를 표시한다. **3D 보기**로 돌아갈 수 있으며 성능이 낮거나 GPU를 사용할 수 없는 환경에서 목록으로 같은 기록을 확인할 수 있다.

## 결과 근거 연결

세션 상세의 **결과 근거 연결**에서 workflow 원장·작업 ID 또는 GitHub PR 주소를 명시적으로 연결한다. 현재 관제실 home 외의 workflow 원장은 먼저 프로젝트 연결에 등록해야 한다. 자동 발견만 된 원장은 선택할 수 없으며, 연결 해제 후에는 기존 근거도 접근 불가로 표시한다. 연결된 작업의 기록된 브랜치·검사 결과와 기존 관리 화면으로 이동할 수 있다. 원장이 삭제·연결 해제되면 접근 불가로 표시하고 다른 원장의 동명 작업으로 자동 대체하지 않는다. 다른 원장을 직접 선택하면 이전 작업 선택을 지운다. 기록된 검사 통과는 현재 코드 재검사나 해당 native 세션 작성 결과의 증명이 아니다. 결과가 없으면 미확인·미실행으로 표시한다.

통합 화면의 **전체 결과 근거**에서도 기존 연결을 조회·해제한다. 원본 세션이 보관 한도로 삭제돼도 연결은 남으며 여기서 직접 정리할 수 있다. 전역 한도는 1000개이고 화면은 20개씩 펼친다.

PR은 GitHub의 HTTPS PR 주소만 지원하며 상태를 새로 조회하지 않는다. 읽기 전용 서버는 연결을 변경할 수 없다. observer의 연결 쓰기는 별도 메타데이터 저장소만 변경하고 workflow 원장·큐를 실행하지 않는다.

## 북마크와 구간 내보내기

세션 상세에서 **현재 세션 구간 저장**을 펼쳐 이름과 처음·마지막 이벤트를 선택한다. 최대 200개의 같은 세션 이벤트 구간을 참조한다. **구간 보기**로 확인하거나 **메타데이터 내보내기**로 JSON을 받는다.

북마크 링크를 열거나 새로고침하면 해당 구간을 다시 표시한다. 생성 시 공급자·소스·원래 세션 ID를 보존하며 원본 정리 후에도 내보내기에서 확인할 수 있다. 이전 북마크에 이 값이 없으면 미기록으로 표시하며 추정하지 않는다.

통합 화면에서도 전체 북마크를 찾을 수 있다. 원본 세션·이벤트가 보관 한도로 정리되면 **근거 만료**로 표시하며, 내보내기는 현재 남아 있는 이벤트만 포함한다. 만료된 북마크도 삭제할 수 있다. 전체 대화·도구 입력/출력은 내보내지 않는다. 최대 500개 북마크를 보관한다.

## 시간·도구 오류 요약

**관측 시간·도구 오류 요약**을 펼쳐 최근 24시간·7일·30일을 선택한다. 현재 프로젝트·도구 필터를 따른다. 저장된 이벤트 이후 최대 300초만 상태 시간으로 인정하고 공백은 미확인으로 분리한다. 동시 세션은 각각 합산하므로 실제 벽시계 시간보다 길 수 있다.

명시적 성공·실패 결과가 있는 도구만 오류율의 분모에 포함한다. 현재 Claude 결과 이벤트를 지원하며 다른 도구는 결과 미확인으로 표시한다. 데이터가 없음을 오류율 0%로 처리하지 않는다. 시계 역전 세션은 시간 합산에서 제외하지만 기간 내 시각이 확인된 도구 오류·결과 수는 유지한다. 전체 저장소의 세션 500개·이벤트 10000개 보관 한도와 현재 수량도 표시한다. 어느 한도든 도달하면 선택 기간의 전체 이력이 남아 있음을 보장하지 않는다고 안내한다. 이 경고는 현재 프로젝트·도구 필터와 별도로 적용한다.

비용·토큰 기능은 사용자 결정으로 이번 범위에서 보류했다.

## 개발 검증과 남은 조건

- WP-OBS-01~14는 패키지별 검사와 지정 독립 리뷰를 통과했다. 초기 01·02·03·05·06은 Claude, 나머지는 사용자 승인 후 별도 Codex 검토다. 최종 문서·통합 변경은 작업 원장의 최신 통합 검토 receipt를 확인한다.
- 실제 Claude 초기화·종료 이벤트, 실제 OpenCode 빈 세션 발견을 격리 환경에서 확인했다. 모델 작업을 실행한 검증은 아니다.
- Codex 직접 훅 설정만으로는 격리 호스트의 훅 목록이 0개였다. 플러그인 설치 후 11개를 인식했으나 모두 untrusted였다. 격리 프로젝트의 신뢰와 한 번 실행의 훅 신뢰 우회를 승인받아 최대 1턴 테스트를 실행했다. 모델 응답은 종료됐으나 30초 동안 관측 DB에 세션이 생기지 않았다. 이후 같은 격리 홈의 `/hooks`에서 관측 플러그인 11개를 명시적으로 신뢰했다. 기존 테스트 세션의 보관 해제·재개·종료만 실행해 실제 `SessionEnd` 수신과 Chromium 상세·이력을 확인했다. 이 종료 실증에는 추가 모델 턴이 없었다. 이후 사용자가 별도로 승인한 최대 1턴에서 `OK` 응답과 `SessionStart → UserPromptSubmit → PreModelRequest → Stop → SessionEnd`를 수신하고 실제 Chromium에서 선택·공간·이력을 확인했다. 최초 1턴과 추가 승인 1턴, 총 2턴이며 자동 재시도하지 않았다. 도구·하위 에이전트 이벤트는 미검증이다.
- 알림 브라우저 검증은 실제 Chromium 두 탭·Web Locks를 사용했다. OS 팝업은 계측 생성자로 대체했으며 OS 표시 자체는 미검증이다. 숨김 상태는 document.hidden을 계측해 조회 지속을 확인했다.
- 10개 원장·1000작업·500세션·10000이벤트의 로컬 합성 HTTP 100회 측정에서 p95 약 47ms. 운영·원격 OpenCode 지연을 보증하는 수치가 아니다.
- 사용자 지시로 새 사용자 3명 파일럿은 **미완료**로 유지한다. 운영 반영 여부와 별개로 REL-01 전체 출시 완료로 판정하지 않는다.

## 운영 반영 전 체크와 복구

별도 브랜치·worktree에서 검증하고 운영 원장·로컬 수정·증거를 보존한다. 운영 checkout pull은 정적 자산도 바꾸므로 배포 시점에 수행한다. 운영 전환은 [운영 절차](OPERATIONS.ko.md)의 jobs·batches·직접 실행·프로세스·백업 검사를 따른다. 이 문서는 8765 관리를 요청하지 않는다.

관측 원장 DB를 병합하지 않는다. 외부 원장 쓰기 없이 연결을 모으고, 기존 URL·관리 기능 접근이 검증된 뒤 포트 정리를 결정한다. 복구 시 이전 소스·정적 자산·관측 home 백업을 사용한다. `session_transitions`는 관측 DB의 추가 테이블이며 외부 workflow 원장 스키마를 변경하지 않는다. 실제 운영 롤백 리허설은 아직 수행하지 않았다.
