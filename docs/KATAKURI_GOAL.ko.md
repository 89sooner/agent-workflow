# Katakuri 목표 연속 실행

Katakuri 개발 목표를 한 번 등록하면 같은 Git 작업 트리에서 구현, 검사, 수정, 독립 검토를 이어간다. 목표만 입력하면 첫 호출에서 저장소 지침과 현재 인계를 읽고 검증 가능한 조건을 나눈다. 완료 조건을 직접 주면 계획 호출을 건너뛴다. 각 단계는 원래 목표, 전체 조건, 최근 체크포인트와 검증 결과를 다시 받는다.

<a id="web"></a>

## React 관제실

1. [8776 관리 화면](http://127.0.0.1:8776/)에서 **새 작업 등록**을 누른다.
2. **프로젝트 설정**에서 수정할 파일에 맞는 프로필을 선택한다. `kb-backtest-tests`는 백테스트 테스트 파일용이다. 엔진 CLI 구현을 수정할 때는 아래의 오프라인 엔진 프로필을 등록한다. [프로필별 범위](../profiles/README.md)
3. **Katakuri 목표 연속 실행**을 체크하고 목표를 입력한 뒤 **작업 등록**을 누른다. 이 선택은 Katakuri 지침과 인계 문서, 수정 범위, 검사, 리뷰어를 갖춘 프로필에서 표시된다.
4. **작업·실행 관리 → 워크플로 실행**을 누른다. 이후에는 브라우저를 닫아도 데몬이 이어간다.

상세 화면에 조건별 상태, 마지막 독립 검토 근거, 모델 호출 수, 실행 시간과 보고 토큰이 표시된다. 대기 조건에 근거를 저장하거나 누적 예산을 조정한 뒤 같은 작업을 다시 실행할 수 있다.

종목과 M1~M6는 선택 사항이다. 예를 들어 HSI M2의 장중 관측이 필요하면 해당 조건에 필요한 자료를 기록하고, 아직 수행 가능한 오프라인 작업을 계속한다. 기존 프로젝트 수락 요건과 종목별 적용 범위를 따른다. 완료는 등록한 개발 목표의 검사와 검토에 대한 판정이다. 실제 모의투자나 실거래 단계의 승격은 별도 운영 절차를 따른다.

<a id="cli"></a>

## CLI

agent-workflow 저장소 루트에서 실행한다. 다음 예제는 실제 파일 기반 엔진 코드와 해당 계약 테스트를 다루는 프로필을 사용한다. 다른 업무에는 그 업무의 수정 경로와 신뢰하는 검사를 지정한 프로필을 사용한다. 등록은 원본 프로젝트의 커밋된 HEAD에서 별도 작업 트리를 만든다. 원본의 미커밋 파일은 포함되지 않는다.

```bash
agent-workflow profile save kb-offline-engine --file profiles/katakuri-offline-engine.json
agent-workflow katakuri-goal create KB-OFFLINE-1 --profile kb-offline-engine \
  --goal 'HSI 오프라인 엔진 CLI의 입력 오류가 원인과 조치 방법을 표시하게 하고 기존 성공 출력을 유지한다' \
  --instrument HSI --max-reported-tokens 120000
agent-workflow queue KB-OFFLINE-1
agent-workflow katakuri-goal status KB-OFFLINE-1
```

대기열 실행은 관리 데몬이 필요하다. 터미널에서 즉시 실행하려면 큐 등록 대신 `agent-workflow katakuri-goal run KB-OFFLINE-1`을 사용한다. 명시적 완료 조건은 `--criterion '…'`으로 여러 개 지정한다. `status`는 모델을 호출하지 않는다.

<a id="resume"></a>

## 멈춘 목표 이어가기

`agent-workflow katakuri-goal status KB-OFFLINE-1`에서 `phase`, `blocker`, 각 조건의 `next_action`을 확인한다. 같은 작업 ID에 다음 조치를 적용한다.

| 상태 | 관제실에서 할 일 | CLI에서 할 일 |
|---|---|---|
| 조건이 외부 자료를 기다림 | 작업 상세에서 해당 조건을 선택하고 **근거 저장 → 워크플로 실행** | 아래의 `supply … --queue`로 제출과 재개를 함께 예약 |
| 모델 호출·시간·보고 토큰 한도 도달 | **누적 예산 조정 → 예산 저장 → 워크플로 실행** | 아래의 `budget`으로 한도를 변경한 뒤 `queue` |
| 인증 또는 공급자 오류 | 차단 이유와 실행 로그를 확인하고 계정 문제를 해결한 뒤 **워크플로 실행** | 같은 ID로 `queue` |
| 완료 | 작업 상세에서 조건별 검토 근거와 검사 결과 확인 | `katakuri-goal status`와 `show`로 기록과 현재 코드에서의 유효성 확인 |

**근거를 기다리는 경우**

```bash
agent-workflow katakuri-goal supply KB-OFFLINE-1 --criterion 2 --ref ./observation.md --queue
```

**예산을 늘리는 경우**

```bash
agent-workflow katakuri-goal budget KB-OFFLINE-1 --max-agent-calls 36 --max-reported-tokens 180000
agent-workflow queue KB-OFFLINE-1
```

<a id="acceptance"></a>

## 완료와 중단

- 실행 담당 모델이 다음 조건을 고른다. 조건이 준비되면 컨트롤러가 등록된 검사 명령을 실행한다. 같은 코드와 참조 파일에서 통과한 검사 결과는 재사용한다.
- 독립 검토자가 모든 조건의 판정과 근거를 반환해야 완료할 수 있다. 실패한 검사는 수정 입력으로 전달하고, 리뷰에서 거절된 조건은 다시 연다. 동일한 입력에서 진척이 없으면 해당 조건을 대기로 전환한다.
- 대기 중인 조건만 남으면 워커가 반환된다. 시세를 폴링하거나 모델을 반복 호출하지 않는다. UTF-8 텍스트 근거는 조건별로 해시를 연결하고 두 모델의 입력에 포함한다. 비밀 정보를 제거하고 필요한 내용만 제출한다. CLI 기준 건별 16 KiB, 목표당 96 KiB까지다.
- 호출 횟수와 누적 실행 시간은 세션을 넘어 유지한다. 보고 토큰 기준은 공급자 응답을 받은 뒤 다음 호출 전에 적용하므로 마지막 호출로 설정값을 넘을 수 있다. 토큰 집계가 누락되면 해당 한도가 있는 동안 추가 호출을 중단한다. 필요하면 `budget ID --clear-token-limit`으로 호출·시간 한도만 유지할 수 있다. 계정 전체의 잔여 토큰은 별도로 조회하지 않는다.
- 실행 환경은 등록한 프로필의 준비·검사 명령을 로컬 권한으로 실행한다. 제공하는 프로필은 파일과 보관된 테스트 데이터를 사용한다. 주문, 브로커 접속, 자동 릴리스는 목표 실행 범위에서 제외한다. 완료 시 작업 트리와 검토 근거가 보존된다.
